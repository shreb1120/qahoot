## Implementation Integrity Verdict

**Split: PASS on product specificity, FAIL on system discipline.**

**What passes.** The report page could not be swapped into another product. The scorecard ring, the per-item Approve/Flag override row, the transcript that highlights the line matching audio position (`report.html:278–290`), and the auto-fail-phrase table are all shaped by the actual compliance-QA job. The history filter set (agent / status / result / date range / client phone) mirrors the real metadata model. The empty states name the actual next step rather than generic filler. Critically, and in line with `PRODUCT.md`'s no-fabrication rule, there are **no invented logos, testimonials, metrics, or customer names** anywhere — the auth-page claims ("AI-powered call analysis against your custom checklist", "Instant pass/fail reports with timestamped evidence", "Manager overrides, PDF exports, and team management") are all true of the shipped product.

**What fails.**

1. **A dead design system is still in the repo.** `templates/index.html` (189 lines), `templates/login.html` (27), `static/style.css` (1,302), `static/app.js` (916) — 2,434 lines total. Nothing renders them: no `render_template` call references either template, and both call `static_v()`, a Jinja helper that **does not exist anywhere in the Python source** — so they would raise on render. Worse, `style.css` declares a *different, conflicting* palette (`--primary: #1e40af` blue, `--bg: #f1f5f9`) than the live indigo system. Anyone reading the repo cold finds two answers to "what color is this product."

2. **The declared token layer is decorative.** `base.html:16–25` defines `brand.*`, `surface.*`, `sidebar.*`, `ok`, `bad`, `warn` in the Tailwind config. Grep across all live templates: **zero** uses of `bg-brand-*`, `text-ok`, `bg-bad`, `text-warn`, or any of them. All 426 color utilities in live templates are raw Tailwind palette (`slate` ×223, `red` ×79, `indigo` ×53, `green` ×26, `amber` ×13, `blue` ×12, `emerald` ×10, `sky` ×8, `violet` ×2). Meanwhile `overrides.css` defines a *third* copy of the same values as CSS custom properties. Three systems, one doing the work.

3. **A repeated visual tell.** The detector flags `border-left: 3px solid <color>` on rounded cards in four files (`report.html:108`, `report.html:173`, `profile/edit.html:25`, `profile/edit.html:121`, `org/settings.html:45`) plus `border-top: 3px solid` on the rounded `.qb-stat` (`overrides.css:68`). The thick one-side accent on a rounded card is the single most recognizable generic-UI signature, and here it is the primary device for distinguishing card types.

## Executive Summary

- **Audit Health Score: 9/20 (Poor)**
- **Issues by severity: 1 × P0, 6 × P1, 12 × P2, 8 × P3**

**Top 5:**

1. **[P0]** The upload file input is unreachable by keyboard *and* silently blocks form submission when empty.
2. **[P1]** Secondary metadata across dashboard, history, and report renders at **~2.6:1** contrast — well under the 4.5:1 AA floor. This is the most-repeated text style in the app.

4. **[P1]** Three history filter controls have **no accessible name at all**; a screen reader announces only the selected option.
5. **[P1]** Every manager override click triggers `window.location.reload()` — losing audio playback position and scroll depth mid-review, which is exactly the moment the reviewer is deepest in the task.

## Detailed Findings

### P0 — Blocking

#### [P0] Keyboard users cannot upload a call, and an empty submit fails silently
- **Location:** `templates/calls/upload.html:29–37`
- **Category:** Accessibility / Correctness
- **Evidence:** The drop zone is `<label id="drop-zone" for="file">`; the control itself is `<input type="file" id="file" name="file" ... required class="hidden">`. Tailwind's `.hidden` is `display: none`, which is emitted independently of the disabled preflight.
- **Impact, part 1:** A `display:none` control is removed from the tab order, and a `<label>` is not focusable. There is therefore **no keyboard path to the file picker** — a keyboard-only or screen-reader user cannot complete the app's primary action. Mouse users are unaffected (clicking a label still activates a hidden input).
- **Impact, part 2:** `required` on a non-focusable control breaks constraint validation. When the form is submitted with no file, the browser cannot focus the invalid control, so Chrome logs *"An invalid form control with name='file' is not focusable"* and **refuses to submit with no visible message**. The user presses "Upload & Analyze" and nothing happens.
- **WCAG:** 2.1.1 Keyboard (A), 3.3.1 Error Identification (A)
- **Fix:** Replace `class="hidden"` with a visually-hidden-but-focusable pattern (`sr-only`: `position:absolute; width:1px; height:1px; clip-path:inset(50%); overflow:hidden`), and add a `:focus-within` ring on `#drop-zone` so the focus is visible. Then validate emptiness in JS and render an inline error, rather than relying on native validation of an off-screen control.
- **Suggested command:** `/impeccable harden`

### P1 — Major

#### [P1] Secondary metadata fails AA contrast app-wide
- **Location:** `overrides.css:22` (`--faint: #94a3b8`, consumed by `.qb-label`); `text-slate-400` throughout — `dashboard.html:32,45,55,68,126,139`; `history.html:112,115,153`; `report.html:20,76`; `upload.html:35,76`
- **Category:** Accessibility
- **Measured:** `#94a3b8` on `#ffffff` = **2.56:1** (needs 4.5:1). `.qb-label` compounds it at 11px/700 uppercase.
- **Impact:** This carries real information — "Uploaded Mar 3", "3 of 7 passed", "Unassigned", the KPI labels, the "Processing…" state. It is not decoration. Anyone reviewing on a laptop in a bright room loses it.
- **WCAG:** 1.4.3 Contrast (Minimum), AA
- **Fix:** Move `--faint` to `#64748b` (4.76:1) and replace `text-slate-400` with `text-slate-500` for anything carrying meaning. Reserve `slate-400` for genuinely decorative glyphs. The footer watermark (`base.html:145`, `text-slate-300` = 1.37:1) can stay if it is truly decorative — but at that ratio, delete it instead.
- **Suggested command:** `/impeccable colorize`

#### [P1] Three of five status badges fail contrast — including the two most common
- **Location:** `overrides.css:119–123`
- **Category:** Accessibility
- **Measured:** `.status-complete` `#059669` on `#ecfdf5` = **3.61:1** · `.status-error` `#dc2626` on `#fef2f2` = **4.41:1** · `.status-pending` `#64748b` on `#f1f5f9` = **4.35:1**. All are 12.8px/600, which does **not** qualify as large text (that needs 18.66px bold). `.status-transcribing` (7.02:1) and `.status-analyzing` (6.55:1) pass.
- **Impact:** Status is the single most-scanned column in history — it is how a reviewer finds work to do.
- **WCAG:** 1.4.3, AA
- **Fix:** Darken the foregrounds: complete → `#047857`, error → `#b91c1c`, pending → `#475569`.
- **Suggested command:** `/impeccable colorize`

#### [P1] History filter controls have no accessible names
- **Location:** `templates/calls/history.html:17, 24, 33, 44`
- **Category:** Accessibility
- **Evidence:** The `agent_id`, `status`, and `result` `<select>`s have no `<label>`, no `aria-label`, and no `title`. The phone `<input>` has only a `placeholder`. The two date inputs carry `title` only, which is unreliable as an accessible name.
- **Impact:** A screen reader announces "combo box, All agents" with no indication of what is being filtered. The placeholder also vanishes on the phone field as soon as typing starts, removing the only cue for sighted users too.
- **WCAG:** 4.1.2 Name Role Value (A), 3.3.2 Labels or Instructions (A)
- **Fix:** Add visually-hidden `<label>`s for each, or `aria-label` at minimum. Given the filter bar is already a dense single row, visually-hidden labels are the lower-risk change.
- **Suggested command:** `/impeccable clarify`

#### [P1] Off-canvas mobile sidebar stays in the tab order
- **Location:** `templates/base.html:64, 159–171`
- **Category:** Accessibility
- **Evidence:** The closed sidebar is hidden with `-translate-x-full` — a transform. The element remains visible to the accessibility tree and focusable. There is no `aria-expanded` on `#sidebar-open`, no `aria-controls`, no Escape handler, no focus trap while open, and no focus return to the trigger on close. `#sidebar-close` has no `aria-label` (the open button does).
- **Impact:** On mobile, a keyboard user tabs from the hamburger straight into seven invisible off-screen nav links before reaching page content. When the sidebar *is* open, focus escapes behind the backdrop into the page underneath.
- **WCAG:** 2.4.3 Focus Order (A), 4.1.2 (A)
- **Fix:** Add `inert` (or `visibility:hidden` at the end of the transition) when closed; toggle `aria-expanded` on the trigger; add `aria-label="Close menu"` on the close button; close on Escape and return focus to `#sidebar-open`.
- **Suggested command:** `/impeccable harden`

#### [P1] Tailwind Play CDN in production
- **Location:** `templates/base.html:9`
- **Category:** Performance
- **Evidence:** `<script src="https://cdn.tailwindcss.com">` plus an inline `tailwind.config` block. This is the Play CDN, which Tailwind's own docs mark as development-only.
- **Impact:** Every page load downloads ~120KB of compiler JS, then scans the DOM and *generates* the stylesheet at runtime. That produces a flash of unstyled content on every navigation — visible here because there is no build step to fall back on. On top of it, the page render-blocks on **three** third-party origins: `cdn.tailwindcss.com`, `fonts.googleapis.com` + `fonts.gstatic.com`, and `cdn.jsdelivr.net` for Clerk. Each is an availability dependency for a tool sold on audit defensibility.
- **Fix:** Add a build step (Tailwind CLI is a single command, no bundler needed) emitting a static `tailwind.css`, and self-host the Inter woff2 files. This also removes the FOUC and makes the `tailwind.config` token layer actually reachable.
- **Suggested command:** `/impeccable optimize`

#### [P1] Manager override reloads the whole page
- **Location:** `templates/calls/report.html:292–305` (`setOverride` → `window.location.reload()`), buttons at `report.html:148–154`
- **Category:** Performance / Responsive
- **Impact (interaction):** The override control lives inside a table row, halfway down a long report, usually while audio is playing. A full reload stops playback, resets `currentTime` to zero, and dumps the reviewer back at the top of the page — every single click. Applying overrides to five items means re-finding your place five times.
- **Impact (touch):** `.ov-btn` (`overrides.css:140`) is `font-size: .72rem; padding: .15rem .45rem` — roughly **18px tall**. `.ts-link` timestamps (`overrides.css:147`) are similarly tiny. Both are well under the 44×44px minimum and sit adjacent to each other.
- **WCAG:** 2.5.5 Target Size (AAA) / 2.5.8 Target Size Minimum 24px (AA, WCAG 2.2) — the override buttons fail even the 24px AA floor.
- **Fix:** Update the cell in place from the JSON response instead of reloading. Raise `.ov-btn` and `.ts-link` to a 24px minimum box (`min-height: 24px; padding: .25rem .5rem`), or collapse Approve/Flag/Clear into one segmented control with proper hit areas.
- **Suggested command:** `/impeccable optimize`, then `/impeccable adapt`

### P3 — Polish

1. **`<code>` renders in Inter.** `*, *::before, *::after { font-family: 'Inter' … }` (`base.html:39`) is a universal selector that overrides the UA monospace default for `<code>`, so auto-fail phrases at `org/settings.html:140` — the one place exact wording matters most — render proportional. Scope the rule to `body` and let `.font-mono` / `<code>` win.
2. **`--brand-200` referenced but never defined** (`overrides.css:62`); the inline `#c7d2fe` fallback always wins.
3. **Heading level skips:** `h1` → `h3` in the history empty state (`history.html:7` → `:59`) and the agents empty state (`agents/list.html:8` → `:66`).
4. **Tables lack `scope="col"` on `<th>` and a `<caption>`** — every table in the app.
5. **No favicon** — tabs show the default globe.
6. **Inter** is detector-flagged as an overused face. Fine for an Operate surface, but it is the reason the app reads as generically modern rather than as itself.
7. **Flat type hierarchy** in `base.html`: 12/14/18/20px, a 1.7:1 total range across four steps. Detector-flagged.
8. **No dark mode.** Reasonable for a v1 internal-facing tool; noting it as a deliberate absence, not a defect.

## Patterns & Systemic Issues

1. **Accessibility was never a pass.** One `aria-label` in 18 templates, ~40 unlabeled decorative SVGs, four unlabeled form controls, a keyboard-unreachable primary input, no skip link, no live regions, no reduced-motion. This is not a set of oversights — it is a dimension that has not been worked on yet. It is also the cheapest dimension to fix here, because the markup is clean, semantic, and server-rendered.
2. **Colors are chosen per-component, not per-system.** Two token systems are declared and neither is used; the 426 color utilities in templates are all raw palette. That is why the admin badge is two different hues and the auth pages are blue in an indigo product — nothing makes the drift visible at edit time.
3. **Small controls cluster where the work is densest.** Overrides, timestamps, and filters — the three highest-frequency interactions — are all 18–30px. Meanwhile the primary CTAs (`.qb-btn-primary`, `py-2.5`) are correctly sized. The scale ran backwards from visual density instead of from interaction frequency.
4. **The repo carries two eras at once.** The live indigo system and a dead blue one, plus an unused token layer. Deleting the dead files is a ten-minute change that removes a whole class of future confusion.

## Positive Findings

- **Genuinely product-specific surfaces.** The audio-synced transcript, the scorecard ring, per-item manager overrides with timestamped evidence, and the auto-fail table are all designed around the real compliance-QA job. This is the hardest thing to get right and it is right.
- **No fabricated proof anywhere.** No fake logos, testimonials, metrics, or customer counts — the auth-page claims are all true of the shipped product. Exactly what `PRODUCT.md` asks for at pre-launch.
- **Empty states do real work.** The zero-state dashboard (`dashboard.html:73–98`) is a genuine three-step activation path to the real routes, not a shrug. History and agents empty states name the next action too.
- **Clean, semantic, server-rendered markup.** Real `<table>`/`<thead>`/`<th>`, real `<form>`s, real `<button>`s, `lang="en"`, correct viewport meta, no div-soup. Everything the a11y fixes need is already in place.
- **Role-gating is consistent.** Every admin-only mutation is wrapped in `{% if g.user.role == 'admin' %}` across profile, agents, and org settings, matching the stated product constraint.
- **Thoughtful upload affordance.** Filename parsing that auto-fills call date and client phone (`upload.html:111–117`) is a small, specific kindness aimed at the actual file-naming convention.
- **The polling architecture is sound.** Backoff on failure, Clerk token refresh, and it stops cleanly when nothing is pending.
